# Step 06: graphs and references

The scripts are numbered in pairs: each drawing script reads the edge list the script before it writes.

Each of the two newsgroup drawing scripts writes its graph twice: as the .html figure described below, and as a .gexf file to be opened in [Gephi](https://gephi.org/). The .gexf file holds the graph itself, the vertices and edges with the attributes they were built from, and names the jaccard overlap or the reference count as the weight Gephi ranks and filters on. Nothing of how the figure is drawn goes in it, so Gephi lays the graph out itself.

Both figures are drawn with vis-network, which brings its own physics: each edge is a spring pulling towards the distance the layout placed it at, so a newsgroup dragged aside takes the ones it is joined to along. A newsgroup is left where it is dropped; double-clicking it hands it back to the physics.

A newsgroup joined to nothing has no edge to hold it, so it is left out of the physics and set out in a row under the graph instead. Above the graph stands what it holds: how many connected sub-graphs the newsgroups with edges fall into, and how many are joined to nothing. Each figure carries the drawing library within it, so it can be opened without a network.

- [01_newsgroup_user_jaccard_overlap.py](01_newsgroup_user_jaccard_overlap.py) computes the Jaccard overlap between the user sets of every pair of newsgroups, reading `data/output/02_build_database/nb.db`. A user is one email address. Creates one row per newsgroup pair sharing at least one user (`newsgroup_a`, `newsgroup_b`, `users_a`, `users_b`, `shared_users`, `jaccard`) in `--output-file` (`data/output/06_graphs_and_references/newsgroup_user_jaccard_overlap_nb.csv` by default). Run with `--overwrite` to rewrite an output file that is already there; without the flag the script exits without doing anything.
- [02_plot_newsgroup_overlap_graph.py](02_plot_newsgroup_overlap_graph.py) draws a graph of newsgroups, with edges based on user overlap. The script reads a `newsgroup_user_jaccard_overlap_*.csv` file written above. A pair becomes an edge if it clears both `--jaccard-threshold` and `--min-shared-users`, and each edge pulls the pair towards a distance of 1 - jaccard, so the more two newsgroups overlap the closer together they are drawn. Every newsgroup in the input file is drawn and named on the picture. Saves an interactive .html figure, named after the input file and the two thresholds, to `data/output/06_graphs_and_references/plot_newsgroup_overlap_graph/`, and the same graph as a .gexf file of that name beside it. (The current script is adapted for the current default input file, the graph layout may look bad if input file is changed). Run with `--overwrite` to redraw them; without the flag the script exits without doing anything when both are already there.
- [03_count_references_between_newsgroups.py](03_count_references_between_newsgroups.py) counts what runs from each newsgroup to each other newsgroup as directed edge lists, reading `data/output/02_build_database/nb.db`. References to messages the NB archive does not hold are counted under a placeholder `unknown` newsgroup, and references within a newsgroup are left out. Every row also carries the referring newsgroup's own total under the same weighting, `references_from_newsgroup` over every reference its messages make and `references_out_of_newsgroup` over the ones reaching another newsgroup or `unknown`, so an edge can be read as a share of what the newsgroup refers to. Creates one row per (from, to) pair (`from_newsgroup`, `to_newsgroup`, `number_of_references`, `references_from_newsgroup`, `references_out_of_newsgroup`), weighted two ways, in `--output-directory` (`data/output/06_graphs_and_references/` by default). Run with `--overwrite` to rewrite output files that are already there; without the flag each of them is skipped.
  - The reference counts add one to the pair's edge for every reference a message in the first newsgroup makes to a message held by the second: `newsgroup_reference_counts_nb.csv`
  - The referenced message counts count how many distinct messages of the second newsgroup are referenced at all, so a message referenced by five hundred messages adds five hundred to the edge above and one here: `newsgroup_referenced_message_counts_nb.csv`
- [04_plot_newsgroup_reference_graph.py](04_plot_newsgroup_reference_graph.py) draws a directed graph of newsgroups, with arrows for the references between them and the two directions between a pair drawn as two curves, reading a reference edge list CSV written above and the `messages_per_group_nb.csv` file from step 03, which sizes the vertices by message count. An edge is drawn if it carries at least `--min-reference-share` of the references leaving the referring newsgroup, so that the considerable size differences between the newsgroups do not decide which edges are drawn, and its width follows the number of references. The `unknown` placeholder is drawn as a diamond unless `--exclude-unknown` is flagged. Every newsgroup drawn is named on the picture. Saves an interactive .html figure, named after the input file, the exclusion flag and the threshold, to `data/output/06_graphs_and_references/plot_newsgroup_reference_graph/`, and the same graph as a .gexf file of that name beside it. Run with `--overwrite` to redraw them; without the flag the script exits without doing anything when both are already there.
- [05_count_references_between_archives.py](05_count_references_between_archives.py) counts each archive's references by which archive resolves them, reading `data/output/02_build_database/ia.db` and `data/output/02_build_database/nb.db`. The vertices are the two archives and a placeholder `unknown` for the references neither of them resolves. Each archive contributes three rows, which add up to its total: a self loop for the references pointing at a message it holds itself, an edge to the other archive for the ones it has lost but the other still holds, and an edge to `unknown` for the rest. A reference is a distinct (referring message id, referenced message id) pair with the newsgroup left out, so the same reply held by several newsgroups or by both archives counts once, and messages with no message id of their own are left out. Both archives are read over the NB date span. Creates one row per (from, to) pair (`from_archive`, `to_archive`, `number_of_references`) in `--output-file` (`data/output/06_graphs_and_references/archive_reference_counts.csv` by default). Run with `--overwrite` to rewrite an output file that is already there.
- [06_plot_archive_reference_graph.py](06_plot_archive_reference_graph.py) draws the edge list written above as a three vertex directed graph, with the placeholder drawn as a dotted `?` circle over the two archives. Every edge carries its reference count beside it, the two arrows between the archives run straight and side by side, and the self loops are drawn as circles hanging under the archives. The three vertices are placed by hand rather than laid out. Saves a .png figure to `--output-file` (`data/output/06_graphs_and_references/archive_reference_graph.png` by default). Run with `--overwrite` to redraw an existing figure.
- [nb_archive_reference_count.py](nb_archive_reference_count.py) counts the references made in the NB archive, reading `data/output/02_build_database/ia.db` and `data/output/02_build_database/nb.db`. A reference is a (referring message, referenced id) pair with the newsgroup disregarded, deduplicated so that a message held by several newsgroups or by both archives counts its references once, and messages with no message id of their own are left out. Both archives are read whole, without a date filter. Writes `total_references`, `resolved_in_nb`, `resolved_in_ia_only` and `unresolved`, which add up to the total, to `--output-file` (`data/output/06_graphs_and_references/nb_archive_reference_count.json` by default).
