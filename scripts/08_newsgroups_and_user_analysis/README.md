# Step 08: newsgroups and user analysis

These scripts are unnumbered because they are independent of each other and can be run in any order.

- [newsgroup_user_jaccard_overlap.py](newsgroup_user_jaccard_overlap.py) computes the Jaccard overlap between the user sets of every pair of newsgroups, reading `data/output/02_build_database/usenet.db`. A user is one hashed email address. Creates one row per newsgroup pair sharing at least one user (`newsgroup_a`, `newsgroup_b`, `users_a`, `users_b`, `shared_users`, `jaccard`) in `data/output/08_newsgroups_and_user_analysis/newsgroup_user_jaccard_overlap_nb.csv`, `data/output/08_newsgroups_and_user_analysis/newsgroup_user_jaccard_overlap_ia_date_filtered.csv` and `data/output/08_newsgroups_and_user_analysis/newsgroup_user_jaccard_overlap_nb_and_ia_date_filtered.csv`
- [count_references_between_newsgroups.py](count_references_between_newsgroups.py) counts the references running from each newsgroup to each other newsgroup as a directed edge list, reading `data/output/02_build_database/usenet.db`. Every reference from a message in one newsgroup to a message held by another adds one to the pair's edge. References to messages not in the read body of messages are counted under a placeholder `unknown` newsgroup, and references within a newsgroup are left out. Creates one row per (from, to) pair (`from_newsgroup`, `to_newsgroup`, `number_of_references`) in `data/output/08_newsgroups_and_user_analysis/newsgroup_reference_counts_nb.csv`, `data/output/08_newsgroups_and_user_analysis/newsgroup_reference_counts_ia_date_filtered.csv` and `data/output/08_newsgroups_and_user_analysis/newsgroup_reference_counts_nb_and_ia_date_filtered.csv`
- [count_referenced_messages_between_newsgroups.py](count_referenced_messages_between_newsgroups.py) counts how many distinct messages in each newsgroup each other newsgroup references, with the same edge list format and the same `unknown` placeholder as the script above: a message referenced by five hundred messages adds five hundred to the edge there and one here. Creates `data/output/08_newsgroups_and_user_analysis/newsgroup_referenced_message_counts_nb.csv`, `data/output/08_newsgroups_and_user_analysis/newsgroup_referenced_message_counts_ia_date_filtered.csv` and `data/output/08_newsgroups_and_user_analysis/newsgroup_referenced_message_counts_nb_and_ia_date_filtered.csv`
- [topic_modelling.py](topic_modelling.py) finds topics with turftopic in the one newsgroup `--newsgroup` names, reading its messages from both archives and its embeddings from step 07. Writes to `data/output/08_newsgroups_and_user_analysis/topic_modelling/<model>/<method>/<newsgroup>[/nr<N>]/`, skipping a run that is already there unless `--overwrite` is flagged.
  - `--method` picks the model: `senstopic` (the default), `s3`, `gmm`, `topeax`, `keynmf` or `clustering`, which is the dimensionality reduction and HDBSCAN pipeline of BERTopic and Top2Vec. `topeax` and `clustering` fit on two t-SNE dimensions, with a perplexity of 50 and 15; the other four fit on the embeddings as they are. Every method except `gmm` and `clustering` loads `--model` to embed the vocabulary.
  - `--nr-topics` is picked by `senstopic`, `gmm` and `topeax` when it is left out, needed by `s3` and `keynmf`, and taken by `clustering` as the number of clusters to reduce to after fitting.
  - Written per run: the fitted model, the topic table (`topic_info.csv`), the highest scoring topic of every document in the order they are loaded (`document_topics.npy`), one JSON object per assigned topic with `topic_id`, the `words` of its highest ranking terms, `nb_message_count`, `ia_message_count` and `total_message_count` (`topic_source_counts.jsonl`), and for `topeax` and `clustering` the two dimensions they reduced to (`reduced_embeddings.npy`).
